# Phase 3 native capability boundary

`startMonitoring` currently accepts only `{consent_version:'consent-v1',motion_consent:true,mode:'MOTION_ONLY_CONFIRMATION',duration_minutes:1..120}`. Default30min. Accelerometer sampling requests50Hz, keeps bounded spike counters only, uses monotonic expiry and stops on Activity pause/account change/stop. It never requests SOS. State reports microphone=false/auto_dispatch=false. Unsupported audio/AUTO_DISPATCH requests fail rather than claiming a detector is active. A graduated model, typed microphoneFGS and native lifecycle evidence remain prerequisites to audio monitoring.

PIN controls configure/enter/reset through native code only. Secrets use separate32byte salts, scryptN32768/r8/p1 and Keystore-encrypted journal storage, no JS persistence/network/analytics. Setup/reset requires provider auth_time≤5min. Wrong attempts persist backoff capped1hour; normal never alerts, practice never alerts, duress uses the existing account-bound SOS intent and Notes screen. PIN does not lock Android or authenticate API calls. OS/notification/network/recipient exposure remains possible. Runtime KDF duration is reported for device benchmarking, not a premeasured claim.

Fake-call schedule accepts label≤80 and delay0..3600sec. Immediate simulation is offline. Background schedule uses inexact AlarmManager plus a normal notification opening the app, not telephony/exact alarms/full-screen privileges. Cancellation releases ringtone/audio focus. Activity pause and audio-focus loss stop sound. Real-device/reboot/call behavior is unverified. Focused key experiment is default off, controlled-demo only, up/down/up/down≤2.5sec with120sec cooldown, preserves normal volume events; no global/power/accessibility interception.

Evidence methods capture ≤10sec16kHz mono PCM audio or a system-camera preview photo only after current owner/evidence consent and active accepted SOS checks. Audio is foreground-only and stopped by pause/call conflict/stopEvidenceCapture. Recipient IDs are selected explicitly and validated server-side; API upload is asynchronous from initial SOS. In-memory media is discarded after one attempted upload; no automatic replay, temporary public files or ambient buffers. Camera full-resolution/video/physical permission/call/lifecycle cases remain unverified. finishAccountDeletion polls the authenticated job then stops all native purposes, wipes encrypted local state and signs out; pending deletion is never presented as completed.

Native TS Codegen seam: [NativeSafety.ts](../specs/NativeSafety.ts). Network DTOs remain generated from the canonical OpenAPI. [Phase3 evidence](../../../docs/validation/phase-3.md) and [Phase4](../../../docs/validation/phase-4.md) separate component/build/device evidence.
