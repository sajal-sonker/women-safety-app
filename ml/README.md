# Offline sound baseline and phrase-model tooling

The app bundles Google's Apache-2.0 YAMNet/classification TFLite v1 (4.13MB) with verified SHA256,521 labels and native CPU inference. See [manifest](models/manifest.json), [attribution](models/NOTICE.md), and [model card](MODEL_CARD.md). Input is raw mono16kHz PCM normalized to float; preprocessing is inside the graph. Android requests50Hz accelerometer samples, uses a3s support window, prompts rather than dispatching, and applies120s prompt cooldown. Strong audio does not require motion. Raw vigorous motion never dispatches. Thresholds are engineering defaults, not calibrated safety probabilities.

`npm run ml:verify` checks the bundled artifact/header/labels. For real desktop interpreter smoke inference, create a Python3.12 virtual environment, install `ml/runtime/requirements.txt`, set `ML_PYTHON` to its Python executable, and run `npm run ml:smoke`. Fixtures are generated silence/tone/noise and establish model execution only. Private results go to ignored `.local/reports`.

## Train a four-class candidate

Create a separate Python3.12 environment with `ml/training/requirements.txt` and point `ML_PYTHON` to it. Run `npm run ml:train -- <private-manifest.json> --output <private-output-directory>`. Classes: NEGATIVE/SCREAM/HELP/BACHAO. Each manifest row has id/path/sha256/consent_ref/license/speaker/session/environment/device/split/duration_s/negative/class. Supply16kHz mono PCM16 WAVs, accurately trimmed/labelled utterances, independent speakers/sessions/environments across train/validation/test, and rights for every asset. Recordings stay outside Git. All four classes must appear in every split. Large negative recordings are split into bounded clips≤10min; only labelled utterance clips should carry phrase labels.

The small CNN consumes log-mel features, with STFT/mel preprocessing included inside the exported waveform-input graph. Training is seeded and streamed with bounded shuffle/prefetch; validation alone controls early stopping. The test set is used only after training for float/quantized decision parity. Export uses LiteRT-compatible builtins and dynamic weight quantization. Output is a **candidate**, never automatically bundled or activated. Review its tensors/checksum/preprocessing, event-level accuracy, quantization divergence and device evidence before deployment. A candidate cannot replace the bundled521class model by renaming a file.

`npm run ml:training-smoke` generates test-only PCM under `.local`, performs one training epoch, exports an actual TFLite candidate and exercises its interpreter/parity path. Those generated labels prove no phrase accuracy. The generated candidate is marked SYNTHETIC_TOOLCHAIN_TEST_ONLY and never enters the APK. Running training without a private manifest exits2 with BLOCKED_EXTERNAL.

## Evaluate real held-out events

`npm run ml:evaluate -- <private-manifest.json> [predictions.json]` verifies file checksums/rights/disjoint splits/minimum support. A prediction document includes model_sha256,thresholds_frozen_before_test:true,threshold and recordings for the exact held-out IDs. Each recording contains id/duration_s/negative/language/device/noise, events[{class,start_s}] and predictions[{class,at_s,score}]. Thresholds must be frozen from validation before inspecting test labels. No test-tuning shortcut exists in the evaluator.

Adjacent predictions within10s form one episode. One correct-class detection0–5s after an annotation matches once. The report includes per-class precision/recall/support/Wilson lower bounds, language/device/noise strata, missed events, detection-delay quantiles and false episodes before/after120s cooldown. The conservative one-sided95% Poisson bound uses pre-cooldown counts and negative exposure; no negatives means no false-alarm claim. Separate audio-only/motion-only/AND/fusion runs must use the same held-out recordings; do not invent benefit from correlated signals. [Graduation gates](../docs/TESTING_AND_ACCEPTANCE_GATES.md) still require≥40speakers,≥150held-out events per class,≥30h negatives, supported devices, parity, energy and independent review. The current baseline has no measured Hindi/English recognition or distress accuracy and cannot enable automatic SOS.
