# Offline sound baseline and phrase-model tooling

## Help and Bachao are implemented in the phone app

The prototype now bundles Vosk small English0.15 and Hindi0.22 pretrained speech models, pinned Android SDK0.3.75 and JNA5.18.1. It recognizes finalized exact **help** and **बचाओ** words from the same consented16kHz PCM stream used by YAMNet. Both languages run together, without network, a second recorder, retained transcripts or saved microphone audio. Word-confidence threshold0.75 and timing checks are engineering filters, not calibrated distress probabilities. One shared120s sound/phrase cooldown asks for manual confirmation; there is no automatic SOS. [Manifest, archive/file hashes and grammars](models/phrases/manifest.json), [attribution](models/phrases/NOTICE.md), [model card](MODEL_CARD.md), [implementation evidence](../docs/validation/help-bachao.md).

`npm run ml:phrases-smoke` runs actual desktop offline recognition against10 committed **generated** speech/silence/noise fixtures, checks archive and extracted-file hashes and requires the expected Help/Bachao/negative labels. Install `ml/runtime/requirements-lock.txt` into the runtime Python environment. No live microphone or participant recording is used. Fixtures were generated by eSpeak NG1.52.0, are explicitly test-only and never enter the APK. To regenerate an ignored trial run with a local eSpeak binary, pass `-- --espeak <executable>`; fixture provenance is in [fixture manifest](test-fixtures/phrases/manifest.json). A successful generated smoke check is not measured human distress accuracy. Physical phone behavior remains to be observed.

The custom four-class CNN below is an optional research extension, not a prerequisite for the implemented pretrained word recognizer.

The app bundles Google's Apache-2.0 YAMNet/classification TFLite v1 (4.13MB) with verified SHA256,521 labels and native CPU inference. See [manifest](models/manifest.json), [attribution](models/NOTICE.md), and [model card](MODEL_CARD.md). Input is raw mono16kHz PCM normalized to float; preprocessing is inside the graph. Android requests50Hz accelerometer samples, uses a3s support window, prompts rather than dispatching, and applies120s prompt cooldown. Strong audio does not require motion. Raw vigorous motion never dispatches. Thresholds are engineering defaults, not calibrated safety probabilities.

`npm run ml:verify` checks the bundled artifact/header/labels. For real desktop interpreter smoke inference, create a Python3.12 virtual environment, install `ml/runtime/requirements.txt`, set `ML_PYTHON` to its Python executable, and run `npm run ml:smoke`. Fixtures are generated silence/tone/noise and establish model execution only. Private results go to ignored `.local/reports`.

## Train a four-class candidate

Create a separate Python3.12 environment with `ml/training/requirements-lock.txt` and point `ML_PYTHON` to it. Classes: NEGATIVE/SCREAM/HELP/BACHAO. Supply16kHz mono PCM16 WAVs, accurately trimmed/labelled utterances, independent speakers/sessions/environments across train/validation/test, and rights for every asset. Recordings stay outside Git. All four classes must appear in every split. Large negative recordings are split into bounded clips≤10min; only labelled utterance clips should carry phrase labels.

Copy the header-only [catalog template](data/catalog.example.csv) to ignored `.local/private-ml/catalog.csv`. Add paths relative to that catalog (or absolute paths), explicit splits and pseudonymous provenance/rights references. `language` and `noise` identify evaluation strata. `event_start_s` is the actual labelled onset for each positive clip; leave it empty for negatives. The tool does not guess consent, labels, onsets or splits. Prepare the checksummed manifest and train:

```sh
npm run ml:prepare -- .local/private-ml/catalog.csv .local/private-ml/manifest.json
npm run ml:train -- .local/private-ml/manifest.json --output .local/private-ml/candidate
```

The small CNN consumes log-mel features, with STFT/mel preprocessing included inside the exported waveform-input graph. Training is seeded and streamed with bounded shuffle/prefetch; validation alone controls early stopping and export parity. Test audio is not inferred during training/export. The pinned TensorFlow2.20 exporter explicitly freezes Keras3 variables to constants, saves a float SavedModel and converts LiteRT-compatible builtins with dynamic weight quantization. Invalid/non-finite outputs fail export before publication; equal argmax values alone are insufficient. Output is a **candidate**, never automatically bundled or activated. Review its tensors/checksum/preprocessing, event-level accuracy, quantization divergence and device evidence before deployment. A candidate cannot replace the bundled521class model by renaming a file. Held-out float/quantized and device review remain graduation prerequisites.

`npm run ml:training-smoke` generates test-only PCM under `.local`, prepares a catalog/manifest, performs one training epoch, exports an actual TFLite candidate and exercises its interpreter/parity path. Then switch `ML_PYTHON` to the runtime environment and run `npm run ml:workflow-smoke` for real validation inference, threshold freeze, test inference and event scoring. It requires the tiny generated dataset to fail graduation. Those generated labels prove no phrase accuracy. The generated candidate is marked SYNTHETIC_TOOLCHAIN_TEST_ONLY and never enters the APK. Running training without a private manifest exits2 with BLOCKED_EXTERNAL. GitHub CI also exercises this pipeline.

## Evaluate real held-out events

Set `ML_PYTHON` to the environment containing `ml/runtime/requirements-lock.txt`. Generate validation predictions, select/freeze the threshold, then run the untouched test split:

```sh
npm run ml:predict -- .local/private-ml/manifest.json --model .local/private-ml/candidate/candidate.tflite --descriptor .local/private-ml/candidate/candidate.json --split validation --output .local/private-ml/validation.json
npm run ml:calibrate -- .local/private-ml/manifest.json .local/private-ml/validation.json .local/private-ml/freeze.json
npm run ml:predict -- .local/private-ml/manifest.json --model .local/private-ml/candidate/candidate.tflite --descriptor .local/private-ml/candidate/candidate.json --split test --freeze .local/private-ml/freeze.json --output .local/private-ml/test.json
npm run ml:evaluate -- .local/private-ml/manifest.json .local/private-ml/test.json .local/private-ml/freeze.json
```

Calibration searches thresholds0.05–0.95 for recall subject to validation precision≥0.90; if that target is unmet it records an uncalibrated best-F1 candidate. Neither status enables dispatch. A freeze is bound to model and manifest SHA256, validation IDs and creation time. Test predictions bind the exact freeze hash; evaluation checks original annotations, exact held-out coverage, file checksums/rights/disjoint splits/minimum support and rejects a boolean claiming thresholds were frozen. Preserve these artifacts for independent review: local timestamps/hashes are reproducibility checks, not proof that a human never inspected or retuned on the test set. Do not rerun threshold selection on test results. Prediction times use the end of each captured window to avoid look-ahead. The final partial stride is scored too.

To evaluate the bundled generic sound baseline instead, pass `ml/models/yamnet.tflite` and `ml/models/manifest.json`. It emits SCREAM only; it cannot pass HELP/BACHAO gates. Missing resources/gates return exit2 rather than inventing a pass.

Adjacent predictions within10s form one episode. One correct-class detection0–5s after an annotation matches once. The report includes per-class precision/recall/support/Wilson lower bounds, language/device/noise strata, missed events, detection-delay quantiles and false episodes before/after120s cooldown. The conservative one-sided95% Poisson bound uses pre-cooldown counts and negative exposure; no negatives means no false-alarm claim. Separate audio-only/motion-only/AND/fusion runs must use the same held-out recordings; do not invent benefit from correlated signals. [Graduation gates](../docs/TESTING_AND_ACCEPTANCE_GATES.md) still require≥40speakers,≥150held-out events per class,≥30h negatives, supported devices, parity, energy and independent review. The current baseline has no measured Hindi/English recognition or distress accuracy and cannot enable automatic SOS.
