# SurakshaAI sound and phrase model card - 11 November 2026

## Offline word recognizer (implemented prototype)

The app bundles unmodified **vosk-model-small-en-us-0.15** and **vosk-model-small-hi-0.22**, both listed by the [upstream model catalog](https://alphacephei.com/vosk/models) under Apache-2.0. Models and API attribution/license are retained in [phrases/NOTICE](models/phrases/NOTICE.md) and [LICENSE](models/phrases/LICENSE-VOSK.txt). Compressed archives total85,664,776bytes; expanded model files total152,983,133bytes. Archive/per-file checksums, sizes, grammar and0.75 minimum ASR confidence are locked in [phrase manifest](models/phrases/manifest.json). Gradle verifies archives, packages only the approved public files and runtime verifies extracted files before loading. Android Vosk0.3.75/JNA5.18.1 runs both languages on the existing microphone stream without network or another recorder.

Finalized exact English **help** or Hindi **बचाओ** words, with finite confidence0.75–1.0 and word duration0.08–3s, can request a check-in without requiring motion. Partial text, missing scores, substrings such as helper/helpful and malformed JSON do not qualify. Decoder history resets at15s to bound continuous-speech state. One shared120s cooldown applies to word/sound prompts. Only HELP/BACHAO labels and aggregate diagnostics cross the native bridge; full transcripts and raw PCM never persist/upload. Stop/expiry/revocation/account/audio conflicts stop the session and release recognizers. Default voice check-ins ask first. A separate default-off, session-only repeated-word SOS option counts five distinct finalized Help/Bachao words within30seconds, then starts a10second cancellable countdown. Counting bypasses the normal120second prompt cooldown, accepts mixed Help/Bachao words and preserves repetitions in one utterance. Bilingual overlapping detections do not count twice. Cancel clears the count and pauses counting30seconds; Stop/expiry/revocation/account change cancel dispatch. Only the local fake-provider prototype accepts the existing ML_FUSION trigger, with active monitoring consent. No real emergency or police dispatch is enabled. The model manifests still mark automatic_dispatch:false: bare model/sound scores never dispatch; the separate opt-in app policy does. This rule is an unvalidated user-requested demo heuristic, not measured distress accuracy.

Actual desktop inference recognizes the four generated positive fixtures and rejects the six tested generated negatives (ordinary phrases, silence/noise). These10 fixtures are toolchain checks, not a human dataset or an accuracy benchmark. Restricted grammars can still confuse ordinary speech/TV with a target; noise, accents, whispers or real distress may be missed. Human precision/recall/false alarms and physical latency/energy/lifecycle are NOT_MEASURED. The prototype does not infer an attack or replace manual SOS. See [phone test](../docs/PHONE_TEST.md).

## YAMNet sound classifier

Disposition: **CONFIRMATION_ONLY_UNVALIDATED**. A real pretrained Google YAMNet/classification TFLite v1 is bundled under Apache-2.0. File/tensors/checksum/labels are locked in models/manifest.json and verified before use. Raw16kHz mono waveform15600 samples produces1x521 sound-event scores; preprocessing stays inside the graph. Screaming is label11. Android uses standalone LiteRT Interpreter1.4.2, the maintained line compatible with the RN template Kotlin2.2;2.3.2's Kotlin2.4 metadata did not compile and is not silently forced into the toolchain.

The bounded, visibly started microphone foreground service keeps inference buffers in memory only. Motion supports a confirmation prompt within3s; strong audio does not require motion. Default thresholds .65 audio-only/.35 with motion and120sec cooldown are engineering settings pending calibration. Sound/motion scores alone never dispatch; only the separately consented repeated-word policy above can request a local demo SOS. Normal manual SOS and separately consented evidence are independent. Stop monitoring before a separate evidence-audio capture; a microphone lease prevents concurrent recorders.

YAMNet itself does not understand Help/Bachao words; the separate Vosk recognizers above implement those words. Neither infers violence or guarantees detection. TV, music and ordinary shouting can cause false prompts; real distress can be missed. Held-out human distress accuracy, phone latency/energy/lifecycle and independent graduation are **NOT_VALIDATED**. No40speaker/30h participant dataset was supplied; that research graduation is outside the prototype target. User will execute physical tests; results are not assumed.

Executed software evidence: actual bundled-model CPU inference on generated silence/tone/noise; native pure fusion tests; synthetic training/export/interpreter execution. These are toolchain tests, not learned phrase accuracy or real-world validation. The generated four-class candidate stays under ignored .local and is never bundled. Real phrase training/export and held-out event/statistical evaluation are implemented; see README.md. Model source/license/attribution: models/NOTICE.md and LICENSE-YAMNET.txt.
