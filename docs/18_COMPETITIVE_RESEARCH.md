## Distinctive product thesis (valid as *our design*, not a superiority proof)

- Temporal route features with reasoned scores/uncertainty rather than one static unsafe-area label.
- Opt-in on-device multimodal potential-distress model integrated into SOS event pipeline.
- Nearest eligible person *among configured contacts* with consented location, not an unrestricted nearby-user network.
- Verified participating shop assistance point (shop response subject to consent and limitations).
- A single response event can combine location freshness, contacts, optional media and acknowledgement while maintaining privacy.
- Discreet duress PIN and tested hardware-key/notification shortcuts as optional triggers.

## Verification protocol before academic presentation

For each competitor collect: official website/store URL, checked date, OS/platform, product feature screenshot/citation, India availability, whether receiver needs app, pricing if relevant, current route/AI features, privacy disclosures. Mark `verified / conflicting / unknown` and quote only verifiable comparisons. Avoid claims that a commercial app definitely lacks a feature based solely on a historical outline.

## Demonstrate difference rather than assert it

Show (1) route time-slider with changing explanation and confidence, (2) auto-sensor inference on staged data with false-positive evidence, (3) recipient browser showing stale/fresh GPS and acknowledgement, (4) opted-in safe-shop availability, (5) fake PIN trigger under a controlled demo. These prove your own functionality without needing to denigrate others.
